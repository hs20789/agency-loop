1 세션 업로드

수업 기간에는 공개·연습용 세션만 올려 주세요 실제 개발 세션 원문은 올리지 마세요.

Claude Code 세션 JSONL 파일 1개(32MiB 이하)를 올리면, 분석에 필요한 항목만 남기고 비밀값·개인정보를 가린 뒤 의사결정 후보를 최대 3개 찾습니다. 파일은 서버 메모리에만 두며 60분 동안 쓰지 않으면 삭제합니다.

  1. 세션 올리기 AI와 함께 개발한 대화 기록(JSONL)을 올립니다.
  2. 결정 하나 되짚기 AI가 중요한 기술적 선택을 한 순간 하나를 골라, 결과를 예측해 보고 분석을 읽으며 원본 기록으로 직접 확인합니다.
  3. 가정 상황 연습 "만약 ~라면?" 질문에 답하고 피드백을 받아 한 번 고쳐 냅니다.
Claude Code 세션이란?

Claude Code는 Anthropic이 만든 AI 코딩 도구입니다. 터미널이나 IDE(VS Code 같은 코드 편집기)에서 실행되고, 내 프로젝트의 코드를 읽고 고치며 명령(테스트 실행 등)도 직접 실행합니다.

세션은 한 프로젝트 폴더에서 Claude Code와 나눈 대화 한 묶음입니다. Claude Code는 작업하는 동안 세션을 내 컴퓨터에 .jsonl 파일로 저장합니다. 한 줄에 기록 하나가 들어 있는 텍스트 파일이며, 여기에는 이런 기록이 담길 수 있습니다.

  • 내가 AI에게 한 요청
  • AI의 답변과 설명
  • AI가 고친 코드
  • AI가 실행한 명령과 그 결과(테스트 결과 등)

Agency Loop는 이 기록에서 AI가 내린 결정, 그 결정의 근거, 결정 뒤에 실행한 테스트를 찾아 보여 줍니다. 그것을 보며 AI의 코드를 이해하고, 직접 검증하고, AI에게 고칠 점을 지시하는 통제를 연습합니다.

claude.ai 웹사이트나 앱에서 나눈 일반 채팅 기록은 Claude Code 세션 파일과 다릅니다. 이 화면에는 Claude Code(CLI)가 남긴 .jsonl 세션 파일만 올릴 수 있습니다. 세션 파일 형식은 Claude Code 내부 형식이라 버전에 따라 바뀔 수 있어, 일부 기록은 분석에서 빠질 수 있습니다.

Claude Code 세션 파일 찾는 방법

내 컴퓨터의 운영체제를 고르세요. 명령은 터미널(Windows는 PowerShell)에 붙여 넣어 실행합니다.

기본 위치 (~는 내 홈 폴더)

~/.claude/projects/

세션 파일 모두 찾기

find ~/.claude/projects -type f -name '*.jsonl'

최근에 바뀐 파일부터 20개 보기

ls -lt ~/.claude/projects/*/*.jsonl | head -20

고른 파일의 복사본 만들기 (<…> 부분을 실제 이름으로 바꾸세요)

cp ~/.claude/projects/<프로젝트 폴더>/<세션 ID>.jsonl ~/my-session.jsonl

.claude처럼 점으로 시작하는 폴더는 숨김 폴더라 파일 선택 창에 보이지 않을 수 있습니다. 복사본을 홈 폴더처럼 찾기 쉬운 곳에 두면 고르기 쉽습니다.

기본 위치 (보통 C:\Users\내 이름\.claude\projects\ · 파일 탐색기 주소 창에 붙여 넣어도 열립니다)

%USERPROFILE%\.claude\projects\

세션 파일 모두 찾기 (PowerShell)

Get-ChildItem "$env:USERPROFILE\.claude\projects" -Recurse -File -Filter *.jsonl

최근에 바뀐 파일부터 20개 보기 (PowerShell)

Get-ChildItem "$env:USERPROFILE\.claude\projects" -Recurse -File -Filter *.jsonl | Sort-Object LastWriteTime -Descending | Select-Object -First 20 LastWriteTime, FullName

고른 파일의 복사본 만들기 (PowerShell, <…> 부분을 실제 이름으로 바꾸세요)

Copy-Item "$env:USERPROFILE\.claude\projects\<프로젝트 폴더>\<세션 ID>.jsonl" "$env:USERPROFILE\my-session.jsonl"

WSL(Windows 안의 Linux)에서 Claude Code를 썼다면 파일은 WSL 쪽 홈 폴더에 있습니다. WSL 터미널에서 Linux · macOS 명령을 쓰세요.

순서

  1. Claude Code를 쓰면 대화가 세션 파일로 내 컴퓨터에 저장됩니다(저장하지 않게 설정할 수도 있습니다).
  2. 파일은 프로젝트(Claude Code를 실행한 작업 폴더)마다 하위 폴더로 나뉘어 있고, 세션 하나가 <세션 ID>.jsonl 파일 하나입니다. 폴더 이름은 작업 폴더 경로에서 글자·숫자가 아닌 문자를 -로 바꾼 것입니다(예: /home/me/weather-app → -home-me-weather-app).
  3. 파일이 많으면 경로(어느 프로젝트인지)와 수정 시각을 보고 원하는 세션을 고르세요. '최근에 바뀐 파일부터' 명령이 도움이 됩니다. 하위 폴더 subagents 안의 .jsonl은 보조 에이전트의 기록이니, 프로젝트 폴더 바로 아래 파일을 고르세요.
  4. 원본은 열어서 고치지 말고 복사본을 만드세요. 원본은 Claude Code가 세션을 이어 갈 때 다시 읽는 파일입니다.
  5. 복사본(.jsonl)을 아래 '파일 선택'으로 올립니다.
  6. 원격 서버에 SSH로 접속해 Claude Code를 썼다면 파일은 그 서버의 ~/.claude/projects/에 있습니다. 내 PC 터미널(Windows는 PowerShell)에서 scp로 안전하게 복사해 오거나, 그 파일에 접근할 수 있는 컴퓨터의 브라우저에서 올리세요. 
    scp 사용자@서버주소:~/.claude/projects/<프로젝트 폴더>/<세션 ID>.jsonl .
  7. Claude Code의 /export 명령으로 저장한 파일은 사람이 읽기 위한 일반 텍스트라 분석할 수 없습니다. 위 폴더의 .jsonl 세션 파일을 올려 주세요.

위치가 다르거나 파일이 없을 수 있는 경우

  • CLAUDE_CONFIG_DIR 환경변수를 설정했다면 ~/.claude 대신 그 폴더 아래 projects에 저장됩니다.
  • 이 안내는 터미널에서 쓰는 Claude Code(CLI) 기준입니다. 데스크톱 앱, 웹(claude.ai/code), VS Code 확장은 세션 목록을 따로 관리합니다.
  • 세션 파일은 기본적으로 30일이 지나면 자동으로 지워집니다(cleanupPeriodDays 설정으로 기간을 바꿀 수 있습니다). claude purge나 직접 삭제로 지웠을 수도 있습니다.
  • CLAUDE_CODE_SKIP_PROMPT_HISTORY 환경변수를 켰거나 claude -p --no-session-persistence로 실행했다면 세션 파일이 만들어지지 않습니다.

Claude Code 공식 문서: 세션 관리(영어) (새 탭에서 열림)

파일을 찾지 못했다면
  • 설정 폴더: CLAUDE_CONFIG_DIR로 저장 위치를 옮기지 않았는지 확인하세요. 터미널에서 echo $CLAUDE_CONFIG_DIR(Windows PowerShell은 echo $env:CLAUDE_CONFIG_DIR)를 실행해 값이 나오면 그 폴더 아래 projects를 보세요.
  • 프로젝트 폴더: Claude Code를 실행했던 작업 폴더의 이름이 들어간 하위 폴더를 보고 있는지 확인하세요.
  • 원격 서버·WSL: Claude Code를 다른 컴퓨터, 원격 서버, WSL에서 실행했다면 파일은 그쪽에 있습니다.
  • 기록 꺼짐·삭제: 기록 저장을 껐거나, 30일이 지나 자동으로 지워졌거나, 직접 지웠을 수 있습니다.
  • 시연 파일로 연습: 아래 '시연 파일로 바로 해 보기'를 누르면 합성 연습 세션을 같은 방법으로 올립니다.

시연 파일

실제 사람의 기록이 아닌, 연습용으로 만든 합성 세션입니다. Agency Loop 저장소의 fixtures/sessions/ 폴더에 있습니다.

  • fixtures/sessions/demo_weather.jsonl — 기본 시연(날씨 API를 부르는 작은 Python 프로그램). 테스트 실패가 기록된 후보가 있어 결과 예측까지 해 볼 수 있습니다. '시연 파일로 바로 해 보기'가 이 파일을 올립니다.
  • fixtures/sessions/many_requests.jsonl — 사람 요청이 6개 이상이라 심층 분석에서 관련 요청 검색까지 볼 수 있습니다. 저장소를 내려받았다면 '파일 선택'으로 이 파일을 고르세요.
파일 크기와 보안 안내
  • .jsonl 세션 파일 1개, 32MiB 이하만 올릴 수 있습니다.
  • 실제 세션 파일에는 API 키, 비밀번호, 회사 내부 코드, 개인정보가 들어 있을 수 있습니다. Claude Code는 세션 파일을 암호화하지 않은 텍스트로 저장하며, AI가 읽은 파일 내용과 명령 출력이 그대로 기록됩니다.
  • 이 앱은 정해진 규칙으로 비밀값·개인정보를 가리지만, 모든 민감 정보가 지워진다고 보장하지 않습니다.
  • 이 MVP에는 로그인이 없고, 암호화되지 않은 HTTP로 연결됩니다. 실제 개인 세션을 올려도 안전한 서비스가 아닙니다.
  • 수업 기간에는 공개 세션이나 합성 연습 세션만 올려 주세요.
  • 이 앱은 내 컴퓨터를 검색하거나 파일을 모으지 않습니다. 내가 직접 고른 파일 1개만 서버로 보내며, 서버는 메모리에만 두고 60분 동안 쓰지 않으면 지웁니다.

        의사결정 후보

        무엇을 고르는 건가요?

        의사결정 후보는 세션 속에서 AI가 중요한 기술적 선택을 한 순간입니다. 예를 들어 오류가 나면 어떻게 처리할지(오류 처리), 외부 API를 어떻게 부를지(외부 호출), 입력값을 어떻게 검사할지(입력 검증) 같은 결정입니다.

        후보 하나를 고르면 그다음 모든 단계가 그 결정 하나를 다룹니다. 고른 뒤에는 이렇게 진행돼요.

        1. 기록 확인 예측 카드에 '기록 확인 예측 가능'이 있을 때만 결정 바로 뒤에 실행한 테스트가 통과했을지 실패했을지, 결과를 보기 전에 예측합니다.
        2. 결과 공개 실제 기록된 결과와 내 예측을 나란히 봅니다. 맞히기 시험이 아니라 코드를 읽고 결과를 상상해 보는 연습입니다.
        3. Claude 심층 분석 + 개발 과정 리포트 그 결정의 이유·대안·가정·위험과 함께 세션 요약, 프롬프트에서 아쉬운 점과 고치는 법, 기록에서 확인되지 않는 부분, 다음 행동 제안을 받습니다. 모든 문장에는 어느 기록에서 왔는지가 붙어 있어 직접 확인할 수 있습니다.
        4. 독립 검토 선택 다른 모델(HCX-007·DeepSeek)의 의견을 받아 Claude와 비교합니다.
        5. 가정 상황(What-if) "만약 상황이 이렇게 바뀌면?" 질문 네 개에 직접 답합니다.
        6. 피드백과 재제출 답변에 대한 피드백을 받고, 한 번 고쳐 다시 낼 수 있습니다.

        선택은 바꿀 수 없어요. 다른 후보의 기록을 보면 이 결정 뒤에 무슨 일이 있었는지(테스트 결과 등) 미리 알게 되어 예측이 의미 없어지기 때문입니다. 다른 후보를 보고 싶으면 같은 세션 파일을 다시 올려 새로 시작하세요.

        카드에는 세션 원문을 넣지 않습니다. 분류별 고정 제목, 코드에서 찾은 신호, 파일, 원문 위치만 보여 줍니다.

        이 세션에서는 코드 변경이 기록된 의사결정 후보를 찾지 못했습니다. 위의 분석 가능 범위를 확인하고, 코드 변경이 기록된 다른 세션을 올려 주세요.

        자기평가

        고른 결정에 대해 지금 내 느낌을 골라 주세요. 정답은 없습니다. 고른 값으로 3단계 가정 상황의 난이도(기본·표준·심화)를 정하고, 마지막 피드백에서 내 답변과 나란히 보여 줍니다.

        이 화면 읽는 법

        AI가 쓴 문장마다 사실인지 해석인지를 알려 주는 배지가 붙습니다. 배지는 AI가 아니라 프로그램(규칙 엔진)이 인용을 원본과 대조해 붙입니다.

        확인이 이 화면의 핵심입니다. 문장에 마우스를 올리거나 '근거' 버튼에 초점을 두면 어느 기록에서 왔는지 미리 보이고, 누르면 아래 원본 기록의 해당 위치로 이동합니다.

        개발 과정 분석 리포트는 심층 분석과 같은 근거 범위에서 만들며, 모든 진술마다 근거 등급을 붙입니다. 리포트는 세션 개발자와 현재 사용자를 다른 사람으로 다루며, 기록에서 확인되지 않는다고 표시한 부분은 실제로 하지 않았다는 뜻이 아닙니다.

        프롬프트 개선 포인트 개발 과정 분석 리포트

        세션 개발자가 AI에게 보낸 요청(프롬프트)에서 구체화하면 좋은 부분입니다. 이전 대화에 맥락이 이미 충분하다면 짧은 요청을 문제 삼지 않습니다.

        판단·검증 보완 포인트 개발 과정 분석 리포트

        기록에서 추가로 확인해 보면 좋은 부분입니다. 개발자의 실력을 판정하는 것이 아니라 기록에서 확인되는 검토 공백을 찾는 것으로, '기록에서 확인되지 않음'은 실제로 확인하지 않았다는 뜻이 아닙니다. 점수나 등급은 없습니다.
